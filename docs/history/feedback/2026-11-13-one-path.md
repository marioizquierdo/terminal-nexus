The owner took up the simplifications proposed at the end of the last pull request: the measurement played through the

### F272 — the measurement done with the skirmish

> What you will simplify next, measurement tool, will be done with the skirmish. I agree, please go ahead and implement that.

**Built.** A measurement's duels are Skirmishes: a new battle's save, each slot seated `script:<player>`, every round
played by `playOn` (`src/skirmish/play.ts`), the one loop the `skirmish` command plays rounds by too. Its own harness
(a duel set up and stepped by hand) is gone. The quick measurement, with three players, plays its 54 duels to exactly
the records it wrote before.

### F273 — the testing saves on one path

> Testing, saves, still open through the engines on path instead of through the battle. Yeah, of course, that is a second way to play. So this can be simplified as well, thank you.

**Built, as one path rather than through the battle.** A testing save tests one rule on the bench's content, with no
Commander, Build Phase or wave; played as a duel's round it would test the duel instead, and every pinned hash would
move. So its one Battle Round has one path of its own, `playTestingRound` (`src/skirmish/sandbox-round.ts`), which
`grid --headless`, `grid --verify`, the `skirmish` command, the measurement and the formations bench all play it by;
the kernel's run takes a watcher, so the hand-written stepping loops (`resolvePulseAt`, the measurement's, the
timeline's) are gone. Every testing save reports as before, the hashes and the `--turn` snapshot included.

### F275 — one reader for the routes and the command's flags

> The game's roots and the command's flags are parsed separately with the same words. Yeah, of course, they could share one parser. It's better that we have like a general way to do the same thing. It's kind of obvious what parts can be reused. It just needs refactoring, and we have plenty of tests and ways to verify that refactoring works. So don't be afraid, go ahead.

**Built.** The words that ask for a Skirmish (`load`, `seed`, `map`, `ticks`, `rounds`, `modifiers`, `p1`, `p2`, each
slot's Commander and credits share) are one table with one reader and one writer (`src/skirmish/ask.ts`). The
`skirmish` command's flags, the game's route and now the game's own flags all go through it, so
`skirmish --map pocket --p2-commander averno`, `terminal-nexus --map pocket --p2-commander averno` and
`--at 'skirmish?map=pocket&p2-commander=averno'` are one battle, refused for the same reasons in the same words. The
route gained what the command had (`ticks`, `rounds`, the credits shares), and on a loaded save the rounds, the
modifiers and the credits shares may change on every door.

### F276 — the words sound through the code and the documents

> Let's complete by making sure that all the new nomenclature is sound through the code and also through the documentation, so the specs and code are synced.

**Built.** The glossary below is the spec, and the code and every current document were checked against it: the
renames below, and each word an audit found used two ways, said one way: a script (`rush`) told from a script profile
(`agro`), controllers written as the save writes them (`player:<name>`, `script:<profile>`) with the screen's labels

words it lacked (banner, hold, the kept front, worker, supply, producer, hand, keep, rarity, PERIMETER).
