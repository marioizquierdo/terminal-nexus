## The Build Phase's way out

### F41 — A visible "end turn" button: `[s] Start`

> the build menu needs a way to visually advertise the action to finalize the phase. This is the
> typical strategy game "end turn" button, usually at the bottom right in the menu and more squared.
> For us, it would be "[s] Start".

**Built.** The menu has a boxed `[s] Start` button at the bottom right of its panel, on every screen
of the Build Phase that can still be edited. It is clickable, `s` presses it, and `p` — the old key —
still works. While a Nexus power is waiting to be picked the button is drawn dim, because pressing it
would only be refused; it still answers a click, with the reason.

### F42 — The confirmation is `[s] Start Pulse 1`, and Enter, `s` or Space press it

> Then the confirmation on the popup should be Enter (or "s" again, space) to "[s] Start Pulse 1".

**Built.** The question is now "START PULSE 1?" with two rows, `[s] Start Pulse 1` (highlighted, so
it is plain what Enter does) and `[n] Keep building`. Enter, Space and `s` start the Pulse; `n`, Esc
and `x` go back to building. `y` still starts it, unlisted, so older scripts keep working. "Pulse 1"
is the mission's first Pulse; the loop that makes a second one is gate 6B's, and the number is data
on the Build Phase's context so it can count then.

## The end of the Pulse

### F43 — The alarm was too much; the title shows a timer and only the timer flashes

> the alarm effect, the red color is too intense, it seems that there will be a nuclear boom like in
> starcraft or something; the anticipation is right. The pulse title should show a timer, and the only
> thing on screen that needs to flash is that timer when it is approaching the last 3 seconds (similar
> to a racing game).

**Built.** The panel's title is now `NEXUS PULSE 1` with a timer at its right end — the time left
until the shooting stops, `0:12` — and in the last three seconds that timer, and nothing else, flashes.
The red banners, the red status line and the red frame are gone. Three seconds is an Experiment
(**Final warning**, 0 turns the flash and the light off). The anticipation he liked is kept: the timer
counts to the stop, and the view still slides back to the Nexus when the last seconds begin.

### F44 — Lighting the border stays, as a light, not a red alert

> Lightning the border of the screen is a nice effect, but the effect should be a light, like if the
> nexus is a light-house calling, not a red alert.

**Built.** In the same last seconds a soft white light sweeps around the frame of the map, like a
lighthouse beam going round: a bright head and a fading tail, one turn a couple of seconds. It only
changes the colour and brightness of the border, never a glyph, so it hides nothing; in monochrome
the beam is the border going bold as it passes; with reduced motion it is one steady soft glow.

### F45 — Red is for the Nexus being hurt, and short and gentle even then

> Reserve the red effect for when the nexus is being damaged (only when first hit, and when life is
> very low and when losing), but even then, make the flashing shorter and less intense.

**Built, with one reading to confirm.** Red now means exactly three things, each a brief, faint
flash of the map's frame: **your Nexus is first hit** (once, about a fifth of a second); **its health
is very low** (below a quarter: a short blip every second and a half while it stays low); and
**losing** — read here as *the moment a lost Pulse's result appears*. If he meant "while my side is
behind", say so and it changes to that. **Red alerts** is an Experiment (on by default) so it can be
switched off.
